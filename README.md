## How I approach a project

1. Define the input, expected output, constraints, and acceptance criteria.
2. Build the smallest complete version that solves the real problem.
3. Test the important paths and failure cases.
4. Document setup, configuration, and handover.
5. Keep credentials, private data, and production access out of source control.
